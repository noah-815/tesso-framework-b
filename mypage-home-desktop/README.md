# Tesso — My Page Home (Desktop)

Framework B `mypage/home` 의 데스크탑(뷰포트 ≥ 768) 구현.
Figma node `7093:89725` (주문 3건) · `7093:89647` (주문 없음).

**확인 목적:** 섹션 `content` 의 `min-height` 를 `mid-120` 으로 뒀을 때 뷰포트별로 적절한가.
우하단 패널에서 주문 건수(0~3)와 min-height 안(mid-120 / mid-100 / 120px 시안값 / off)을
바꿔가며 비교할 수 있고, 읽기값에 **min-h 계산값 · 실제 콘텐츠 높이 · 적용 여부**가 표시됩니다.

```
index.html      # 마크업 + 전체 스타일
assets/         # Figma 익스포트 썸네일 3종 (288px 로 리사이즈)
```

## 측정 결과 — mid-120

`min-height` 의 목적은 **내용이 적을 때도 일정한 높이를 확보해 레이아웃이 튀지 않게** 하는
것입니다. 막아야 할 대상인 주문 1건의 높이는 뷰포트가 두 배가 돼도 **91 → 101px 로 거의
고정**입니다 (썸네일 72px 이 px 고정이라). 반면 `mid-120` 은 83 → 157px 로 움직입니다.

굵게 표시된 것이 min 이 실제로 걸린 경우입니다.

| viewport | `mid-120` | 0건 | 1건 | 2건 | 3건 |
|---|---|---|---|---|---|
| 1280 | 82.7px | 41.1 → **82.7** | 90.7 → 90.7 | 173.3 | 256.0 |
| 1440 | 92.0px | 42.4 → **92.0** | 92.0 → 92.0 (동일) | 175.0 | 258.0 |
| 1512 | 96.2px | 43.0 → **96.2** | 92.6 → **96.2** | 175.7 | 258.9 |
| 1920 | 120px | 46.4 → **120** | 96.0 → **120** | 180.0 | 264.0 |
| 2560 | 157.3px | 51.7 → **157.3** | 101.3 → **157.3** | 186.7 | 272.0 |

- **0건**은 전 구간에서 걸립니다.
- **1건**은 **1440px 을 기점**으로 갈립니다. 1440 에서 두 값이 정확히 92px 로 만나고,
  그 아래(1280)에서는 걸리지 않습니다.
- **2건 이상은 어느 뷰포트에서도 영향 없습니다** (173px 이상).
- 2560 에서는 101 → 157px 로 **56px 빈 공간**이 생깁니다.

### mid-100 과 비교

| viewport | `mid-100` | `mid-120` | 고정 `120px` |
|---|---|---|---|
| 1280 | 69.3px (1건 ✕) | 82.7px (1건 ✕) | 120px (1건 ○) |
| 1440 | 77.0px (1건 ✕) | 92.0px (경계) | 120px (1건 ○) |
| 1512 | 80.4px (1건 ✕) | 96.2px (1건 ○) | 120px (1건 ○) |
| 1920 | 100px (1건 ○, 4px) | 120px (1건 ○, 24px) | 120px (1건 ○) |
| 2560 | 130.7px (1건 ○, 29px) | 157.3px (1건 ○, 56px) | 120px (1건 ○) |

mid-100 은 1건 커버가 1819px 이상에서만 됐는데, **mid-120 은 1440px 부터로 내려왔습니다.**
1512·1920 같은 실사용 해상도를 포함하게 된 건 개선입니다. 다만 1280 은 여전히 빠지고,
2560 에서 벌어지는 빈 공간은 오히려 커집니다.

### 참고

가변 토큰인 이상 "1건을 항상 커버"하려면 최저 뷰포트(1280)에서 101px 이상이어야 하고,
그러려면 값이 커져서 2560 에서는 더 크게 벌어집니다. 전 구간 일관성이 필요하면 고정 px
(시안 현재값 120px)가, 큰 화면에서 여백이 늘어나는 걸 의도한다면 mid-120 이 맞습니다.

### 2. spacing

```css
--us: calc(100vw / 1920);
--mid-4: 4px; --mid-6: 6px; --mid-8: 8px;      /* 값 ≤ 8 → 고정 */
--mid-12:  calc(  4 * var(--us) + 8px);
--mid-16:  calc(  8 * var(--us) + 8px);
--mid-24:  calc( 16 * var(--us) + 8px);
--mid-32:  calc( 24 * var(--us) + 8px);
--mid-40:  calc( 32 * var(--us) + 8px);
--mid-56:  calc( 48 * var(--us) + 8px);
--mid-72:  calc( 64 * var(--us) + 8px);
--mid-80:  calc( 72 * var(--us) + 8px);
--mid-100: calc( 92 * var(--us) + 8px);
--mid-120: calc(112 * var(--us) + 8px);
--mid-160: calc(152 * var(--us) + 8px);
```

| 영역 | 값 |
|---|---|
| titleArea | 상하 padding `mid-56` |
| tabArea | 상단 padding `mid-72` |
| main | 상단 `mid-80` / 하단 `mid-160` |
| greeting | gap `mid-8`, 하단 padding `mid-40` |
| section | 상하 padding `mid-32` |
| sectionHead | gap `mid-24`, 하단 padding `mid-16` |
| sectionBody | **min-height `mid-120`** (검증 대상), 상단 padding `mid-24` |
| order 목록 gap | `mid-12` · 아이템 내부 `mid-16` / `mid-24` / `mid-6` / `mid-4` |
| profile 블록 gap | `mid-32` · 내부 `mid-12` / `mid-8` |

### 3. 그리드

12컬럼 / 거터 16px / 좌우 19px — 모두 px 고정.
`tabArea` = 1~3컬럼, `main` = 4~9컬럼 (10~12는 비움).
1920 에서 tabArea 458.5px, main 933px 로 시안과 일치합니다.

### 4. 그 외 px

header 64px, 탭 항목 상하 padding 8px, 썸네일 72px, divider 1×12px, hairline 1px,
`전체보기`·`프로필 관리` 밑줄 버튼 padding 1/2px.

### 5. 폰트

```css
--font: "Work Sans", "Pretendard Variable", Pretendard, sans-serif;
```

`2025. 12. 31.`, `208,000`, `010-1234-1234` 같은 숫자는 Work Sans, 국문은 Pretendard.

## 참고

- **가격 숫자 min-width** — 컴포넌트 정의가 `10ch` 라 그대로 적용했습니다. 브라우저에서
  Work Sans Medium 13px 기준 **81.7px** 로 계산되어, 시안의 렌더값 99px 과는 다릅니다
  (`ch` 를 Figma 와 브라우저가 다르게 계산). 시안 폭을 그대로 맞추려면 99px 로 두면 됩니다.
- 우하단 데모 패널은 시안에 없는 요소입니다. `.demo-nav` / `.demo-seg` / `.demo-readout`
  CSS 와 `#demoNav` 마크업, 그 아래 스크립트를 지우면 됩니다.
- 프로필 섹션의 `content` 도 같은 `min-height` 를 씁니다. 내용이 항상 250px 을 넘어
  실질적으로는 영향이 없습니다.
