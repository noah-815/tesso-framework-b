# Tesso — My Page Home (Desktop)

Framework B `mypage/home` 의 데스크탑(뷰포트 ≥ 768) 구현.
Figma node `7093:89725` (주문 3건) · `7093:89647` (주문 없음).

**확인 목적:** 섹션 `content` 의 `min-height` 를 `mid-100` 으로 뒀을 때 뷰포트별로 적절한가.
우하단 패널에서 주문 건수(0~3)와 min-height 안(mid-100 / 120px 시안값 / off)을 바꿔가며
비교할 수 있고, 읽기값에 **min-h 계산값 · 실제 콘텐츠 높이 · 적용 여부**가 표시됩니다.

```
index.html      # 마크업 + 전체 스타일
assets/         # Figma 익스포트 썸네일 3종 (288px 로 리사이즈)
```

## 결론부터 — mid-100 은 min-height 로 잘 동작하지 않습니다

`min-height` 의 목적은 **내용이 적을 때도 일정한 높이를 확보해 레이아웃이 튀지 않게** 하는
것입니다. 그런데 `mid-100` 은 뷰포트에 따라 69 ~ 131px 로 움직이는 반면, 막아야 할 대상인
**주문 1건의 높이는 91 ~ 101px 로 거의 고정**입니다. 두 값이 1819px 부근에서 교차해서,
그 아래에서는 1건일 때 min 이 아예 안 걸리고 위에서만 걸립니다.

| viewport | `mid-100` | 0건 | 1건 | 2건 | 3건 |
|---|---|---|---|---|---|
| 1280 | 69.3px | 41.1 → **69.3** | 90.7 → 90.7 | 173.3 | 256.0 |
| 1512 | 80.4px | 43.0 → **80.4** | 92.6 → 92.6 | 175.7 | 258.9 |
| 1920 | 100px | 46.4 → **100** | 96.0 → **100** | 180.0 | 264.0 |
| 2560 | 130.7px | 51.7 → **130.7** | 101.3 → **130.7** | 186.7 | 272.0 |

굵게 표시된 것이 min 이 실제로 걸린 경우입니다. 정리하면,

- **1건**에서 min 이 걸리는 구간은 **1819px 이상**뿐입니다. 1280·1512 에서는 무효.
- 1920 에서 걸리긴 하지만 96 → 100px, **4px 차이라 눈에 안 보입니다.**
- 2560 에서는 101 → 131px 로 **30px 빈 공간**이 생깁니다.
- **2건 이상은 어느 뷰포트에서도 영향 없습니다** (173px 이상).

즉 mid-100 은 사실상 **0건(빈 상태) 전용**으로만 동작하고, 그마저도 확보되는 높이가
69 ~ 131px 로 뷰포트마다 두 배 가까이 차이 납니다.

### 시안 현재값 120px 과 비교

| viewport | `mid-100` 0건 / 1건 | `120px` 0건 / 1건 |
|---|---|---|
| 1280 | 69.3 / — | **120 / 120** |
| 1512 | 80.4 / — | **120 / 120** |
| 1920 | 100 / 100 | **120 / 120** |
| 2560 | 130.7 / 130.7 | **120 / 120** |

고정 120px 은 전 뷰포트에서 0건·1건 모두 일관되게 걸립니다.

### 제안

`min-height` 는 **내용 높이를 기준으로 정하는 값**이지 뷰포트를 따라갈 이유가 없습니다.
주문 아이템 높이(72px 썸네일)가 px 고정이므로 min-height 도 px 고정이 맞습니다.

- 지금처럼 **120px 유지** — 1건까지 확실히 커버 (`mid-24` + 72 = 최대 101px 보다 큼)
- 굳이 토큰을 쓰겠다면 `mid-*` 대신 **px-\* 계열**로 정의

## 단위 체계

디자인 기준 폭 **1920**.

### 1. 타이포그래피

| 토큰 | 쓰임 | @1280 | @1920 | @2560 | 처리 |
|---|---|---|---|---|---|
| `caption-2` 12px | 주문일 | 12px | 12px | 12px | 고정 |
| `paragraph-4` 13px | 탭 · 상품명 · 가격 · 라벨 | 13px | 13px | 13px | 고정 |
| `paragraph-3` 14px | 섹션 타이틀 · 설명 · 값 | 14px | 14px | 14px | 고정 |

### 2. spacing

```css
--us: calc(100vw / 1920);
--mid-4: 4px; --mid-6: 6px; --mid-8: 8px;      /* 값 ≤ 8 → 고정 */
--mid-12:  calc(  4 * var(--us) + 8px);
--mid-16:  calc(  8 * var(--us) + 8px);
--mid-24:  calc( 16 * var(--us) + 8px);
--mid-32:  calc( 24 * var(--us) + 8px);
--mid-40:  calc( 32 * var(--us) + 8px);
--mid-56:  calc( 48 * var(--us) + 8px);
--mid-72:  calc( 64 * var(--us) + 8px);
--mid-80:  calc( 72 * var(--us) + 8px);
--mid-100: calc( 92 * var(--us) + 8px);
--mid-160: calc(152 * var(--us) + 8px);
```

| 영역 | 값 |
|---|---|
| titleArea | 상하 padding `mid-56` |
| tabArea | 상단 padding `mid-72` |
| main | 상단 `mid-80` / 하단 `mid-160` |
| greeting | gap `mid-8`, 하단 padding `mid-40` |
| section | 상하 padding `mid-32` |
| sectionHead | gap `mid-24`, 하단 padding `mid-16` |
| sectionBody | **min-height `mid-100`** (검증 대상), 상단 padding `mid-24` |
| order 목록 gap | `mid-12` · 아이템 내부 `mid-16` / `mid-24` / `mid-6` / `mid-4` |
| profile 블록 gap | `mid-32` · 내부 `mid-12` / `mid-8` |

### 3. 그리드

12컬럼 / 거터 16px / 좌우 19px — 모두 px 고정.
`tabArea` = 1~3컬럼, `main` = 4~9컬럼 (10~12는 비움).
1920 에서 tabArea 458.5px, main 933px 로 시안과 일치합니다.

### 4. 그 외 px

header 64px, 탭 항목 상하 padding 8px, 썸네일 72px, divider 1×12px, hairline 1px,
`전체보기`·`프로필 관리` 밑줄 버튼 padding 1/2px.

## 참고

- **가격 숫자 min-width** — 컴포넌트 정의가 `10ch` 라 그대로 적용했습니다. 브라우저에서
  Work Sans Medium 13px 기준 **81.7px** 로 계산되어, 시안의 렌더값 99px 과는 다릅니다
  (`ch` 를 Figma 와 브라우저가 다르게 계산). 시안 폭을 그대로 맞추려면 99px 로 두면 됩니다.
- 우하단 데모 패널은 시안에 없는 요소입니다. `.demo-nav` / `.demo-seg` / `.demo-readout`
  CSS 와 `#demoNav` 마크업, 그 아래 스크립트를 지우면 됩니다.
- 프로필 섹션의 `content` 도 같은 `min-height` 를 씁니다. 내용이 항상 120px 을 넘어
  실질적으로는 영향이 없습니다.
